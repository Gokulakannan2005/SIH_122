1. EXECUTIVE SUMMARY & PROBLEM CONTEXT
================================================================================
In mega-construction and EPC infrastructure projects (such as thermal power plants,
refineries, and metro rail networks), there is a severe disconnection between two worlds:

A. THE FIELD REALITY:
   Site supervisors produce hundreds of raw, unstructured, informal daily updates
   across multiple formats (handwritten daily reports, Excel progress trackers,
   voice notes, and WhatsApp photos with trade slang like "Hydro done on CW line").

B. THE SCHEDULE BASELINE:
   Project planners maintain thousands of formal L5/L6 milestone activities in
   Primavera P6 or Microsoft Project (e.g., "Activity PIP-L6-012: Erect Line 24-CW-017,
   WBS 2.1.2, Pump Bay").

THE DATUM SOLUTION:
Datum bridges this multi-crore reconciliation gap with a deterministic, explainable
Multi-Factor NLP and Spatial Matching Engine backed by human-in-the-loop planner
verification, cryptographic photo evidence provenance, and predictive schedule
delay simulation.

3. IN-DEPTH BUG FORENSICS: DISCOVERIES, ROOT CAUSES & RESOLUTIONS
================================================================================

BUG 1: RIGHT-SIDE NAVBAR OVERFLOW AND BROKEN HORIZONTAL TABS
- Observation: As new tabs (Supervisor Portal, AI Copilot) and status pills were added,
  the horizontal top navigation bar overflowed and clipped on standard laptop displays.
- Root Cause: Horizontal flex layouts without wrapping constraints fail when tab count
  exceeds 5 items on viewports <= 1440px width.
- Resolution: Refactored the architecture into an enterprise-grade Fixed Left Sidebar
  (260px) + Minimal Top App Header, categorizing tabs into logical groups (Field Operations,
  Schedule & Reconciliation, AI Pipeline).

BUG 2: SQUISHED, UNSTYLED TYPEWRITER TEXTAREAS AND TRUNCATED INPUTS
- Observation: Textareas in supervisor view appeared as tiny fixed boxes with unstyled
  typewriter fonts (Courier), and supervisor names were truncated on the right.
- Root Cause: Missing CSS classes (`.form-input`, `.form-textarea`, `.form-select`,
  `.form-label`) in stylesheet caused browsers to render default 20-col x 2-row HTML inputs.
- Resolution: Defined high-precision form styling with `width: 100%`, `min-height: 84px`,
  smooth focus rings (`0 0 0 3px rgba(2, 132, 199, 0.16)`), and responsive grid wrapping.

BUG 3: STALE TASK SELECTION PERSISTING AFTER QUEUE COMPLETION
- Observation: When all tasks in a filtered review queue were approved, the details
  pane continued to show the data of the last approved task instead of disappearing.
- Root Cause: `activeUpdateId` state held a stale ID string that was no longer in `queueItems`,
  causing the view to render the stale item from the master array.
- Resolution: Rewrote active item resolution to be strictly derived from `queueItems`.
  When `queueItems.length === 0`, it renders a dedicated "All Tasks in This Queue Reconciled! 🎉"
  celebration card with zero stale memory.

BUG 4: SCORE FACTOR BREAKDOWN OVERLAPPING IN INSPECTOR DRAWER
- Observation: In the Inspector side drawer, the 4 score factors (Keyword, Discipline,
  Area, Fuzzy) collided and overlapped into an unreadable string.
- Root Cause: Plain text formatting with fixed width overflow inside narrow 380px drawer.
- Resolution: Replaced with a 2x2 structured chip grid featuring animated progress bars,
  high-contrast fractional scores, and expanded drawer width to 480px.

BUG 5: RESTART / RESET DEMO BUTTON NON-RESPONSIVE
- Observation: Clicking "Reset Demo" did not clear user selections or provide visual feedback.
- Root Cause: State variables (`selectedInspectorUpdateId`, `selectedReviewUpdateId`,
  `offlineSyncQueue`) were not wiped on reload, and no async feedback toast was triggered.
- Resolution: Explicitly cleared all selection pointers, purged offline queues, re-parsed
  fresh baseline files, and added a floating green confirmation toast.

BUG 6: SUPERVISOR COULD ACCESS PLANNER REVIEW CONTROLS
- Observation: Supervisors clicking "Review" in the field stream could enter the Planner
  Match Matrix and modify schedule links.
- Root Cause: Universal "Review" buttons in `SiteUpdatesView.tsx` were not role-gated.
- Resolution: Implemented strict role check (`currentRole !== 'supervisor'`). For supervisors,
  all buttons are locked to read-only "Inspect", and administrative tabs are hidden.

4. ROLE-BASED ACCESS CONTROL (SUPERVISOR VS LEAD PLANNER)
================================================================================

A. SITE SUPERVISOR PERSONA (Field Worker / Subcontractor):
   - Access: Field Progress & Photo Logs, Daily Field Reports Feed (Read-Only),
     Milestone Baseline L5/L6 (Read-Only Reference).
   - Permissions: Submit daily progress, upload photos/documents, report site blockers.
   - Prohibitions: Cannot approve matches, cannot alter schedule baselines, cannot edit
     confidence weights.

B. LEAD PLANNER / ADMIN PERSONA (Project Management & Control Room):
   - Access: Complete 7-module enterprise suite.
   - Permissions: Full authority to approve algorithmic links, manual re-linking,
     classifying unplanned work, modifying extracted parameters, adjusting schedule
     variances, and exporting certified audit CSVs.
